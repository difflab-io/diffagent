# Provisional choice after the fixed-task POC

**Keep Rig as the initial Rust agent backend, but preserve the backend boundary and keep Ax available for the declarative-flow experiment.** This is an architecture choice, not a claim that Rig outperformed Ax: both passed all four independent acceptance runs in this small sample. Ax averaged **22.8 seconds and $0.003026 estimated off-peak per run**, versus Rig's **27.2 seconds and $0.004330**; see the [per-run evidence](SUMMARY.md). The difference is too small a sample to establish a reliable provider/runtime performance advantage, especially because generated code lengths, cache state, and run order differ.

Rig's native async provider and typed tool contracts fit a headless Rust engine that will later serve a TUI and desktop UI. Ax's Rust `AxGen` did demonstrate a working model→tool→model loop, but its blocking HTTP path requires `spawn_blocking`, and its dynamic signature/response interface uses JSON values. Ax's `flow()` features remain interesting for branching orchestration; this POC uses diffagent's own YAML graph, so it **does not compare the libraries' native graph implementations**. The current results cannot resolve that architectural question.

Before making a long-term commitment, test more representative **multi-file** changes, persistence/resume, cancellation, streaming events, provider switching, and a cross-platform sandbox. Neither this limited 2-task × 2-run comparison nor tests that run generated code under macOS `sandbox-exec` establish production safety. Review the exact [fixtures](fixtures/), [tool-call traces](results/), and [raw metrics](summary.json) before changing the recommendation.
