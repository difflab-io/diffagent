# Coding workspace

Read relevant source and tests before changing code.
Keep changes in the workspace.
Use only configured named tasks or mise tasks for execution.
Use a suitable named task first.
If none fits, list mise tasks and reuse a suitable one before adding a task.
If neither fits, read the workspace `mise.toml` and add one focused task there.
In chat, run a relevant build or test after editing.
In a YAML flow, do not repeat the graph's test node without a reason.
Inspect failed output and fix the cause when possible.
A write preview is not proof that a file changed.
Report what you tested and any failure plainly.
